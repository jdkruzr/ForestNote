# Ink Domain (core:ink)

Last verified: 2026-08-24 (Boox live-surface/committed-View split on Kaleido)

## Purpose
Abstracts device-specific e-ink input/display transport behind a common interface and provides the stroke data model, coordinate system, and geometry operations used by all other modules. Both accelerated backends can own pen input: Onyx/Boox drives the firmware raw-drawing pipeline (`TouchHelper`/`RawInputCallback`), while Viwoods direct mode receives `ENoteWritingInputListener` samples on ENote's worker thread and immediately draws app-owned pixels through `renderWriting(...)`. The shared ingest seam (`StrokeSink`) lets either feeder reuse the same accumulation/render/persistence path. Viwoods can be switched back to its older display-only/Android-`MotionEvent` path at runtime.

## Contracts
- **Exposes**: `InkBackend`, `Stroke`/`StrokeBuilder`/`StrokePoint`, the 17-value portable `BrushKind`, deterministic `CanonicalBrushRenderer`, `PenVariant`/`PenParams`, `PageTransform` (including exact `updatePage(screenW,screenH,pageW,pageH)`), tools/text boxes, geometry/eraser policy, and the shared `StrokeSink` ingest seam.
- **Guarantees**: `BackendDetector.detect()` always returns a working backend (GenericBackend fallback). All stroke/point data uses virtual coordinates. PageTransform is the sole virtual-to-screen converter. Generic and Viwoods-fallback mode do not own input; Boox and Viwoods-direct mode do. Input, required host-surface topology, and retained-page display ownership are independent contracts (`ownsInput()`, `requiresInputSurface()`, `ownsPageDisplay()`).
- **Expects**: Android Context for backend init. View dimensions for PageTransform.update(). Boox additionally expects a sibling host `SurfaceView` + a `StrokeSink` + the active `PageTransform` (via `attachInput`/`setTransform`); Viwoods direct input binds to DrawView itself and does not need a SurfaceView.

## Dependencies
- **Uses**: Android framework, Viwoods ENote APIs (via reflection), Jetpack Ink geometry, **Onyx/Boox Pen SDK** (`onyxsdk-pen:1.5.4`, `onyxsdk-device:1.3.5`, `onyxsdk-base:1.8.5` — `TouchHelper`/`RawInputCallback`/`EpdController`, used only by `BooxInkBackend`, runtime-gated to Onyx; repo is cleartext HTTP, see `settings.gradle.kts`) + `hiddenapibypass:6.1` (mandatory on minSdk 30: the Onyx SDK reflects hidden APIs — `HiddenApiBypass.addHiddenApiExemptions("")` runs before any SDK call)
- **Used by**: `core:format` (Stroke/StrokePoint types), `app:notes` (everything)
- **Boundary**: Must not depend on `core:format` or `app:notes`. The `StrokeSink` *implementation* (`DrawViewStrokeSink`) lives in `app:notes` (it touches the bitmap + `NotebookStore`); only the contract + value types live here, so `InkBackend.attachInput(host, sink, …)` type-checks without crossing the boundary.

## Key Decisions
- Reflection bridge for Viwoods APIs: device SDK is undocumented, reflection isolates from API changes and allows compilation on any machine
- Virtual coordinate space (short axis = 10,000): strokes are resolution-independent across device orientations and screen sizes
- Millipressure (0-1000 int): avoids float precision issues in storage and serialization
- Logarithmic pressure curve: `width = min + range * ln(3p+1) / ln(4)`, matches Viwoods first-party feel
- **Input-ownership seam:** `InkBackend` exposes defaulted input/display lifecycle methods: `ownsInput()`, `requiresInputSurface()`, `ownsPageDisplay()`, `attachInput(host, sink, excludeRects)`/`detachInput()`, `setTransform`, `onTransformChanged`, `updatePen`, `setActiveTool`, `setInputSuspended`, `setOverlayExcludeScreenRect`, `setOnFirmwarePenDown`, `onResumeReacquire`, `reconcileRepaint`, `commitInkStroke`, and `cleanNextReconcile`. Android MotionEvents, Boox raw input, and Viwoods direct callbacks all terminate in the same `StrokeSink`, so stored stroke DATA is identical across platforms — the hard cross-device compatibility constraint.
- **Portable committed pixels (2.0):** vendor enums/styles are closest-match live previews only. Every stroke stores `BrushKind` + brush version + deterministic seed and optional per-point tilt/orientation. On pen-up `DrawView` clips to the stroke dirty rect, clears the approximation, and replays the full static layer stack through `CanonicalBrushRenderer`; the backend publishes those exact pixels. Reloads, thumbnails, PDF/SVG export, Viwoods and Boox therefore share one committed rendering authority.
- **Viwoods direct path:** `ViwoodsBackend` opts into unofficial SDK `directInputCallbacks(true)`, draws immediately into a synchronized preview bitmap on ENote's HandlerThread, and posts accepted canonical samples to `StrokeSink` on the host thread. View geometry is captured on the UI thread and frozen for a gesture; never query/mutate a View from the callback. Input exclusion/suspension handles popups and overlays. Root is not required.
- **Isolated-point guard:** the direct Viwoods path holds only a >72px jump for one callback and drops it only when the next point returns within 24px. This targets the observed one-sample 112px view-origin teleport without delaying normal samples or deleting legitimate consecutive fast motion. `IsolatedPointSpikeFilter` is pure and unit-tested; a drop logs raw, origin, local, and callback timing fields.
- **Onyx has TWO INDEPENDENT firmware switches** (the non-obvious crux, proven on-device): `TouchHelper.setRawDrawingEnabled(bool)` = the MASTER (stylus capture + raw callbacks) and `TouchHelper.isRawDrawingRenderEnabled` (property) = the firmware's direct-to-panel ink PASSTHROUGH. They are NOT coupled — master OFF + passthrough ON still draws live ink with no callback. `BooxInkBackend.applyFirmwareEnableState()` is the single source of truth: it drives BOTH to `firmwareShouldBeLive()` (= `!inputSuspended && activeTool is Pen`). Treat capture and render as separate axes; never force render `true` blindly.
- **Canvas-only firmware surface, host-owned committed page:** Boox's sibling SurfaceView exists only because `TouchHelper` requires it and provides the near-zero-latency direct-to-panel preview. DrawView remains opaque above it and owns the retained page. At pen-up it redraws the canonical dirty rect through the ordinary Android View pipeline. This split is essential on Kaleido: the same neutral RGB gray is colorless in an ordinary View but turns green/blue when committed through `refreshScreenRegion(surface, ...)`, even in GC. `reconcileRepaint` therefore drops stale firmware ink by suspending render, invalidates the host View, settles (300 ms mono / 500 ms colour), then restores `firmwareShouldBeLive()`; a requested clean reconcile performs display-wide GC only after the host frame is posted.
- **Per-stroke append commit (`commitInkStroke`):** firmware ink is only the live preview. The completed canonical stroke is published by `DrawView.invalidate(dirtyRect)`, never blitted into the Boox SurfaceView. `commitInkStroke` records trace timing and arms the debounced render-only un-freeze; on Android 13/Tab Ultra this remains delayed 8 seconds so its render-off settle cannot interrupt ordinary handwriting. `runUnfreeze` invalidates DrawView after dropping the transient firmware layer, so the retained page is always restored from the canonical bitmap.

## Invariants
- StrokePoint coordinates are always in virtual space, never screen pixels
- PageTransform is the ONLY class that converts between virtual and screen coordinates
- ViwoodsBackend.isAvailable() returns false on non-AiPaper devices (checks ENoteSetting class)
- Sub-strokes from splitStroke() always have 2+ points
- `Stroke.id` is a client-minted ULID (String), defaulted to `Ulid.generate()` at construction — every stroke has a stable id from creation, no "unsaved" state
- `StrokeGeometry.reconcileErase` mints fragment ids via an injected `newId: () -> String = Ulid::generate` factory, keeping it pure and deterministically testable

## Key Files
- `InkBackend.kt` - Backend interface. Display-accelerator surface (init, startStroke, renderSegment, endStroke, pushBackgroundBitmap, resetOverlay, release) PLUS the defaulted input/display-ownership surface (`ownsInput`, `requiresInputSurface`, `ownsPageDisplay`, attachInput/detachInput, transform/tool/suspension state, reconcile/commit and transition refresh methods)
- `StrokeSink.kt` / `InkSample.kt` / `InkPhase.kt` - Device-agnostic ingest seam fed by EITHER the MotionEvent feeder (Viwoods/Generic) or the firmware raw-input feeder (Boox). `StrokeSink.begin/accept(sample, phase)/cancel`; `InkSample.from(x, y, pressure01, ts, transform)` converts to virtual+millipressure; `InkPhase` = DOWN/MOVE/UP. Impl `DrawViewStrokeSink` lives in `app:notes`
- `ViwoodsBackend.kt` - AiPaper fast ink via the unofficial Viwoods SDK: direct ENote callback-thread input by default, app-owned synchronized preview bitmap, dirty-rect `renderWriting`, UI-thread canonical `StrokeSink` posts, hardware-erasure batching, popup exclusion, screenshot/repaint reconciliation, and display-only Android-input fallback
- `IsolatedPointSpikeFilter.kt` - Pure one-sample confirmation guard for rare Viwoods coordinate-origin teleports
- `BooxInkBackend.kt` - Onyx/Boox firmware raw drawing (`ownsInput()=true`, `requiresInputSurface()=true`, `ownsPageDisplay()=false`): `TouchHelper`+`RawInputCallback` → `StrokeSink`; firmware-thread→UI hop via `surface.post`; per-move accumulation guards against broken batch starts; two-switch enable state; transient live SurfaceView under an opaque canonical DrawView; coalesced freeze/host-repaint reconcile; debounced render-only un-freeze. Defensive throughout (developer-hostile device + hidden-API reflection)
- `GenericBackend.kt` - Fallback using standard View.invalidate()
- `BackendDetector.kt` - Runtime backend selection, priority Viwoods (`ENoteSetting`) > Boox (`MANUFACTURER==ONYX` + `TouchHelper` present) > Generic. Gates are mutually exclusive; Generic is the guaranteed fallback if a backend's `init()` throws. (No manual override Setting — auto-detect only.)
- `Stroke.kt` - Immutable Stroke (ULID id) + mutable StrokeBuilder
- `TextBox.kt` - Immutable TextBox (ULID id; virtual-coord x/y/width/height + fontName/fontSize/color/weight/borderWidth) + `ZBand` enum (BOTTOM=below ink, TOP=above everything; stored as the `z` int)
- `Ulid.kt` - Dependency-free, time-sortable ULID generator (stroke/page identity)
- `PageTransform.kt` - Virtual/screen coordinate conversion + zoom/pan viewport (`fitScale`/`zoom`/`scale`, `viewportX/Y`, `setZoom`/`panByScreen`/`resetToFit`). `update(w,h,longAxis=VIRTUAL_LONG_AXIS)` fits a stable `VIRTUAL_SHORT_AXIS × longAxis` page with a uniform scale (letterbox, never distort); `longAxis` is per-notebook. `templatePitchVirtual(mm)` = `mm × VIRTUAL_UNITS_PER_MM` (=80; page nominally 125mm wide) — a FIXED device-independent page quantity, NOT derived from any device ppi/fitScale, so template lines land at the same virtual coords as the (device-independent) ink on every panel. `pageRectScreen()` projects the page rect to screen px (feeds the Boox firmware limit rect). The old `ppi` field is GONE (the physical-mm-via-ppi conversion was the cross-device drift bug)
- `PageBounds.kt` / `PageBoundsGate.kt` - Pure off-page pen policy (FCIS). `PageBounds.contains/clamp` = page-rect test + edge clamp; `PageBoundsGate` = per-stroke state machine (`begin`/`admit(sample, phase, longAxis)`): a DOWN off-page drops the whole stroke (latches until next `begin`), mid-stroke samples off-page are clamped to the edge. Used by the shared `DrawViewStrokeSink` so BOTH feeders (MotionEvent + Boox firmware) get identical bounds. Eraser + lasso deliberately bypass it (must still reach legacy off-page strokes)
- `ScreenRect.kt` / `FirmwareLimitRectLogic.kt` - Pure page-rect-in-screen-px value type + the Boox firmware limit-rect math: `compute(pageRectScreen, canvasTopOffset, surfaceW, surfaceH)` outsets the page rect to whole px (never inset — the gate is authoritative), shifts by `canvasTopOffset`, intersects the canvas; empty/invalid → full-canvas fallback (never a dead pen)
- `StrokeGeometry.kt` - Intersection testing and stroke splitting for erasers. `reconcileErase` has an **AABB fast-reject** (output-preserving): the eraser path's radius-inflated bounding box is computed once, and any stroke whose point-AABB doesn't intersect it skips the O(m·k) segment loops — since every point the segment test inspects lies inside the stroke box, a disjoint box proves no erase. Turns the common case (erase touching a few of many strokes) into an O(n) box check; a property test in `StrokeGeometryReconcileTest` pins byte-identical output vs. the naive triple loop

## Gotchas
- Viwoods hidden API calls are isolated in `~/vw_ink_sdk_unofficial`; app-side backend code
  should treat SDK startup/render failures as recoverable and fall back to normal View drawing.
- WritingBufferQueue is a shared device resource: release() in onPause, reacquire() in onResume
- Re-acquire on resume now goes through `InkBackend.onResumeReacquire()` (Viwoods re-acquires its WritingBufferQueue; Boox re-enables raw drawing) — the old "`ViwoodsBackend.reacquire()` is off-interface, caller must cast" gotcha is RETIRED (the cast would have crashed on the Boox backend)
- **Onyx SDK quirks (all measured on-device, worked around in `BooxInkBackend`):** (1) `TouchHelper.setExcludeRect(emptyList)` is a NO-OP — it applies a non-empty list but ignores an empty one, so "clearing" an exclude leaves a permanent dead zone; `currentExcludeRects()` never returns empty (substitutes a 1px sentinel). (2) Re-latching the exclude set MID-STROKE doesn't take → defer the clear to `onEndRawDrawing` (gate on `strokeInProgress`). (3) `setStroke*` config calls SILENTLY RE-ENABLE the firmware engine → re-assert `applyFirmwareEnableState()` after any pen-style change. (4) `getMaxTouchPressure()` varies per unit (4095 vs 4096), so always query. (5) the batch callback `onRawDrawingTouchPointListReceived` is unreliable on some firmware (fired 4/11 on Note Air5 C), so accumulate from per-move callbacks. (6) suspending `isRawDrawingRenderEnabled` wipes the firmware ink layer globally; repaint DrawView from the canonical bitmap whenever it is toggled. (7) a SurfaceView-scoped refresh can tint neutral grayscale on Kaleido even when the framebuffer and screenshot are neutral; never commit retained page pixels through the raw-input SurfaceView.
- **`BooxInkBackend.mainHandler` MUST be `by lazy`** — an eager `Handler(Looper.getMainLooper())` field-init crashes `BackendDetectorTest`/`BackendIntegrationTest` ("Looper.getMainLooper not mocked"), because detection CONSTRUCTS `BooxInkBackend` to probe `isAvailable()`. Lazy defers the Looper touch to first on-device use. Same trap awaits any future Android-framework field initializer in a detected backend.
- Onyx callbacks may arrive on a firmware thread (or `main` on some units); `BooxInkBackend` hops to the UI thread via `surface.post` so the single-threaded `StrokeSink` is never touched off-thread. Keep `onEndRawDrawing` LIGHT — heavy work there blocks the firmware's touch release and stalls the next interaction.
